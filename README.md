# 📊 Monthly Excel Manager

![.NET](https://img.shields.io/badge/.NET-8.0-purple)
![C#](https://img.shields.io/badge/C%23-WinForms-blue)
![Version](https://img.shields.io/badge/version-1.2.3-2b7a78)

> 실제 업무에서 반복되던 작업을 줄이기 위해 만든 WinForms 기반 데스크톱 자동화 도구입니다.

`Monthly Excel Manager`는 처음부터 범용 업무 프로그램을 목표로 만든 것이 아닙니다.  
**특정 사용자의 실제 업무 흐름에 맞춰 필요한 작업을 자동화하기 위해 시작했고, 사용 중 나온 요청과 불편을 반영하면서 기능을 확장해 온 프로젝트**입니다.

---

## 💛 왜 만들었을까?

여자친구 회사에서는 네이버 카페 게시글을 하나씩 열어

- 조회수
- 댓글 수
- 작성일

등을 확인한 뒤 다시 Excel에 직접 입력하는 작업을 반복하고 있었습니다.

단순한 작업이지만 건수가 쌓일수록 시간이 오래 걸리고, 반복 입력에서 실수와 피로도도 늘어났습니다.

그래서 처음에는 **Excel의 URL 목록만 넣으면 필요한 게시글 정보를 수집하고 결과 Excel을 만들어주는 프로그램**으로 시작했습니다.

이후 실제 업무에 사용하면서 새로운 요청이 생길 때마다 블로그 정리, 이미지 처리, 검사기, 사용자 설정까지 필요한 기능을 하나씩 추가했습니다.

저는 이런 식으로 **반복적인 확인·복사·정리 작업이 보이면 필요한 범위를 자동화해서 사람이 쓰는 시간을 줄이는 방식**을 선호합니다.

---

## 🎯 이 프로그램이 해결하는 문제

- 게시글 정보를 하나씩 확인하고 Excel에 다시 입력하는 반복 작업
- 블로그 본문 정리와 이미지 저장을 수작업으로 반복하는 과정
- 키워드·글자수·번역 등 여러 작업을 위해 도구를 따로 열어야 하는 번거로움
- 프로그램 수정 후 사용 환경마다 새 파일을 다시 전달해야 하는 배포 과정

즉, **특정 업무에서 반복되는 웹 조회·정리·Excel 작업을 하나의 프로그램으로 묶어 낭비를 줄이는 것**이 목표입니다.

---

## 🔧 주요 기능

- **크롤링** — Excel URL 목록을 기반으로 네이버 카페 게시글 정보를 수집하고 결과 Excel 생성
- **키워드 정리** — 입력한 키워드를 자동 분리하고 목록 형태로 정리·복사
- **블로그 정리** — WebView2 기반 네이버 블로그 본문 정리, 새로고침, 이미지 다운로드
- **이미지 변환** — 이미지 목록 확인, 미리보기 및 일괄 포맷 변환
- **검사기** — 사람인 글자수 도구와 Papago 번역기를 한 화면에서 전환
- **사용자 설정** — 탭 표시/숨김, 순서 변경, 배율 등 사용 환경 저장
- **자동 업데이트** — GitHub Releases의 최신 manifest를 확인해 변경 파일을 반영한 뒤 프로그램 실행

## 👤 현재 사용 범위

현재 프로그램은 **특정 업무와 실제 사용자의 작업 흐름에 맞춰 만든 전용 자동화 도구**입니다.

범용 RPA나 모든 사이트에서 사용할 수 있는 크롤링 프로그램을 목표로 하지 않으며, 네이버 카페·블로그 등 현재 업무에서 필요한 대상과 작업 방식에 맞춰 구현되어 있습니다.

따라서 대상 사이트의 DOM이나 실제 업무 방식이 변경되면 그에 맞는 수정이 필요합니다.

## 🧩 설계 방향

### 1️⃣ 직접 조회 → 자동 수집
사람이 게시글을 하나씩 열어 확인하던 과정을 Excel URL 목록과 Selenium 기반 수집으로 변경했습니다.

### 2️⃣ 단일 기능 → 업무 흐름 통합
처음에는 카페 크롤링만 필요했지만 실제 사용 요청에 따라 키워드, 블로그, 이미지, 검사 기능을 하나의 프로그램 안으로 확장했습니다.

### 3️⃣ 기능 증가 → 역할별 구조 분리
기능이 늘어나면서 `Pages / Handlers / Processors / Controls / UI / Utils`로 역할을 나눠 WinForms 코드가 한곳에 몰리지 않도록 구조를 정리했습니다.

### 4️⃣ 멈추는 작업 → 취소 가능한 백그라운드 처리
Selenium 크롤링 중 UI가 멈추는 문제를 줄이기 위해 작업을 백그라운드로 분리하고 `CancellationToken`, 진행률 표시, 중복 실행 방지, 동시 작업 수 제한을 적용했습니다.

### 5️⃣ 수동 전달 → GitHub Releases 자동 업데이트
실제 사용자가 있는 만큼 수정할 때마다 프로그램 전체를 다시 전달하는 과정도 줄이고 싶었습니다.

별도의 `Monthly_Excel.Launcher`가 GitHub Releases의 `releases/latest` manifest를 확인하고, SHA-256 기준으로 필요한 파일을 갱신한 뒤 본 프로그램을 실행하도록 구성했습니다.

릴리즈용 파일과 `manifest.json`, portable ZIP 역시 PowerShell 스크립트로 생성할 수 있도록 정리했습니다.

## 🔍 트러블슈팅

### 크롤링 중 UI 멈춤

Selenium 기반 크롤링이 동기적으로 수행되면서 작업 중 프로그램을 사용할 수 없었습니다.

크롤링을 백그라운드 작업으로 분리하고 `CancellationToken`을 전달해 취소할 수 있도록 변경했습니다. 완료 건수 기반 진행률과 실행 중 버튼 상태도 함께 제어하고, 과도한 동시 실행을 막기 위해 worker 수를 제한했습니다.

### WebView2 초기화 충돌

블로그 탭에서 `already initialized with a different CoreWebView2Environment` 오류와 초기 `about:blank` 화면이 발생했습니다.

CoreWebView2 상태를 확인해 중복 초기화를 방지하고, Navigation 이벤트 중복 등록을 막았습니다. 또한 초기화 후 기본 페이지를 이동시키고 실제 본문 DOM이 준비된 이후 정리 스크립트를 실행하도록 보완했습니다.

### 배포와 업데이트 반복

실제 사용 중인 프로그램이라 기능을 수정할 때마다 최신 파일을 다시 전달해야 했습니다.

이를 줄이기 위해 Launcher에서 GitHub Releases의 최신 manifest를 조회하고 변경된 파일만 갱신하도록 구성했습니다. 릴리즈 asset과 manifest 생성 과정도 PowerShell로 자동화해 개발 환경이 달라도 동일한 방식으로 배포할 수 있도록 했습니다.
